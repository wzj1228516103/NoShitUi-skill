# 展示项目扩展规划

状态：规划阶段；本文件中的新增项目尚未实施。

本次依据现有 7 个概念页的源码、合集入口和桌面截图评估覆盖范围。现有页面的视觉方向已比较丰富，下一阶段重点补充产品类型、页面结构、任务流程和组件选型证据，同时继续保留有辨识度的视觉与动效。

## 主要缺口

1. **业务组件密集的应用**：数据表格、筛选、排序、分页、表单校验、编辑抽屉、批量操作。
2. **空间与画布交互**：地图和列表联动、配置控件驱动 3D 场景、节点连接与参数编辑。
3. **持续使用的工具**：播放进度、队列、学习进度、文档搜索和本地恢复。
4. **移动优先的任务流程**：底部导航、日历时段、分步填写、确认和取消。
5. **资源选型的可核验结果**：新示例需要记录需求、采用的组件方案、取舍和实际验证，说明 Skill 如何从推荐走到实现。

## 第一批的具体范围

### PRECISION：先证明业务 UI 的选型与落地

- 使用 30 条固定演示订单，字段包含编号、客户、金额、状态、日期。
- 支持文本搜索、状态筛选、列排序、分页和选择记录。
- 编辑抽屉允许修改状态与备注，保存后反映到列表。
- 表单展示一处有意义的必填/格式错误；筛选无结果时提供清除条件入口。
- 移动端使用精简列和详情入口，保留同一套筛选与编辑能力。
- 达成标准：可以完成一次查找与修改，刷新后的保存行为符合页面说明；表格、抽屉和通知使用一致的组件体系。

### DRIFT：让空间交互成为主体

- 使用 12 个固定演示地点，包含分类、位置、说明和停留时间。
- 地点卡片与地图标记双向联动；选中项保持明显状态。
- 支持加入、移除和调整行程顺序，地图同步绘制演示路线。
- 路线连接与时间估算明确作为演示，不作为真实导航结果。
- 移动端以地图配合底部地点面板呈现；无需用户实际定位即可完成流程。
- 达成标准：从地点发现到形成行程可完整操作，刷新可恢复行程；地图加载失败时仍能浏览地点列表。

### OBJECT：将 3D 变为产品操作

- 展示一款原创模块化桌灯，模型用几何体构建，减少外部模型依赖。
- 支持旋转、缩放、3 种材质、2 种灯罩和亮度控制。
- 切换配置时真实更新模型；价格、已选项和配置摘要来自同一份状态。
- 给材质切换加入短过渡，将灯光变化与亮度参数直接关联。
- 达成标准：用户可以完成配置、看到变化、查看摘要并重置；WebGL 不可用时仍能查看静态产品和参数摘要。

## 实施顺序

1. **第一批：运营后台 → 地图探索 → 3D 配置器。** 先补充可验证的业务组件，再加入空间探索和沉浸式产品操作。
2. **第二批：节点画布 → 播放器 → 预约日历。** 扩展拖拽连接、媒体状态和多步表单。
3. **第三批：移动学习 → 开发者文档。** 补充移动优先和长内容工具场景。

每个示例先完成一个核心流程，再加入加强该流程的动效。例如：保存记录的状态反馈、地图焦点切换、材质过渡、节点运行路径、与真实音频时间同步的波形。原有电商、内容和音乐节可以在后续补齐各自的代表性流程。

## 统一交付约定

- 每页使用独立的视觉规则：字体比例、间距、颜色、导航结构和信息密度在设计阶段确定。
- 固定演示数据支持重置；保留需要持续使用的本地状态，并说明保存范围。
- 为核心任务覆盖有意义的加载、空结果、校验错误、失败反馈、成功确认和恢复路径。
- 验证桌面和窄屏、键盘操作、焦点返回、触控目标；动效尊重减少动态效果设置，昂贵渲染在离屏时暂停。
- 为每个新示例保留简短选型记录：需求、候选方案、选择理由、资源来源与许可、集成约束、实际验证结果。
- 基础 UI 选型来自 Skill 资源目录；地图、节点、音频等专项库在采用前核对官方来源、兼容性、许可和维护证据。
- 沿用现有静态展示入口；需要框架的应用独立构建，将可部署产物接入合集。

## 展示与仓库安排

- 合集增加按“品牌与内容 / 业务应用 / 沉浸式体验 / 创作工具”浏览的入口。
- 每个项目提供封面、类型、一句核心操作说明和进入体验的链接；进入页面即可完成核心任务。
- 为新项目补桌面、移动端和关键交互状态截图，更新 README 的轻量预览。
- README 继续以 Skill 为中心；示例仅辅助说明其输出能力。
- 网站源码、选型记录和部署流程放在 `showcase-source`；主分支保留 Skill 文档与精选素材。

后续可扩展金融分析、招聘/人才社区、餐饮点单等主题，优先复用已经验证的交互模式；只有出现新的结构或任务能力时，再新增独立概念页。
